Patient Report — Redesign Preview · OpenELIS Global Jasper (patient_letter.jrxml / patient_a4.jrxml)
Redesign intent — what changes vs the current JRXML

Current patient.jrxml — issues

  • Hard-coded French static text "Nom, Prenom(s)" in the first-page demographics frame (bypasses $P{localization})
  • Flat 9pt SansSerif everywhere — no typographic hierarchy between facility name, patient name, and result values
  • Patient demographics packed into 84pt with 11 bordered cells — hard to scan
  • Stranded demo backcolors (#FF9999, #66FF66, #33FFFF) in page-2 frame that only render if prints-when conditions are edited
  • Abnormal flagging confined to a 34pt "alert" column (H/L/*) — entire row gives no visual cue
  • No visual distinction between merely abnormal and critical (panic-range) values — both appear identical on the printed page despite the clinical-notification difference
  • No critical-value notification audit on the report — clinical call gets logged in OpenELIS but the printed report doesn't carry the trail (CAP/CLSI noncompliance risk)
  • Send-out tests show only an R flag — performing lab name + their accreditation reference are absent (ISO 15189 §7.4.1.6 noncompliance for accredited labs)
  • Corrected reports paint a banner but never identify the version they supersede or summarize what changed (ISO 15189 §7.4.1.7 noncompliance)
  • No specimen-quality interference signal — a hemolyzed potassium reads as a real critical hyperkalemia and the clinician can't tell from the report
  • Legend at bottom is two cryptic lines of letter codes
  • Gender column 28pt wide (~single letter), age column 33pt — awkward widows when "Unknown" or translated "Femme" appears
  • Corrected-report banner text is plain and bold-13pt but not color-coded

Redesigned layout — what the dev implements

  • Every visible string driven by $P{localization} — no hard-coded French, no English fallback text embedded in JRXML
  • Type scale aligned to Style Guide v1: facility 14pt, title 18pt semibold, patient name 15pt semibold, results 10.5pt tabular-nums, labels 8.5pt uppercase
  • Two-column demographic card — same 38 fields, roomy, scannable in under 2s
  • Abnormal results flagged on the full row (left-edge color rule + soft row tint) in addition to the alerts column — driven by the existing abnormalResult boolean field
  • Critical (panic-range) values flagged with a visibly thicker 6pt left-edge rule, double-arrow glyph (⇈/⇊), darker row tint, and an inline "CRITICAL" chip — survives B&W photocopy and draws the reviewer's eye instantly. Derived from existing ResultLimit.criticalLow / criticalHigh; no new bean field.
  • Critical-value notification audit rendered both inline (italic footnote under each critical row with phone glyph + recipient + readback) and as an end-of-report appendix table for the surveyor view. Fixes CAP/CLSI compliance gap. Backend = new result_critical_notification audit table + validator-UI prompt at notify time (§14(d)).
  • Performing-lab disclosure on R-flagged rows replaces the method sub-line with "Performed by [external lab]". Fixes ISO 15189 §7.4.1.6 referral-lab disclosure gap. Backend = plumb through existing Referral entity (§14(c)). Home-lab test accreditation is governed by a separate Test Accreditation epic (parent + 4 sub-issues) which renders body logos in the report header — that epic is not modified by this redesign.
  • Report version + supersedes line on corrected issues — italic white line inside the gold banner identifies prior version date and summarizes the change. Fixes ISO 15189 §7.4.1.7 corrected-report identification gap. Backend = new patient_report_issue version-history table (§14(e)).
  • HIL specimen-quality chip slot reserved in the result-row sub-line area, parameterized on specimenQualityFlags. Dormant in production until the §18 HIL backend epic ships across the analyzer framework — at which point the chip lights up across every deployment with no template change. Designed now so the chip ships ready when the data arrives.
  • Report-status chip ("Partial" / "Complete" / "Corrected") in a Carbon-style Tag in the top-right of the header — replaces the boldface "Corrected Report" centered banner when a subtler signal suffices
  • Compact single-line legend
  • Panel parent/child visually distinct — parent row shaded, child rows indented 14pt
  • Carbon color + typography tokens applied: brand navy #295785, ink #161616, error #da1e28, IBM Plex Sans (falls back to Helvetica in Jasper)

Corrected report — version & supersedes line (Round 4 §7.1a)

When correctedResult == true and reportVersion > 1, the corrected banner extends with an italic version line showing the prior issue date and a one-line summary of what changed. ISO 15189 §7.4.1.7 hard requirement. The banner stays a single gold frame so both lines sit on the same background.

Corrected Report
Report v2 — Supersedes v1 issued 12 Apr 2026 10:24. Changes: Hemoglobin corrected from 11.3 to 12.3 g/dL after instrument recalibration; potassium added (verbal preliminary on 13 Apr).

First issues (reportVersion == 1 or null) suppress the version line entirely. The banner appears only on corrected issues. The full audit chain — every prior version with its issue date and correction summary — is available via the §7.9 cross-reference (when present) or the new patient_report_issue table per §14(e).

Field map at a glance (full table in spec .md)

38 of the original 39 fields still map 1:1 from the current patient.jrxml. The redesign adds 9 new bean fields + 6 new parameters, sized as follows: small / same-PR ready — methodName (§14a), HH/LL derived into alerts (§14b), performingLabName + performingLabAccreditation (§14c), accreditation params (§7.7a). Medium / its-own-ticket — five critical-notification fields + criticalNotifications list (§14d), four report-version params (§14e). Large / separate epic — specimenQualityFlags for HIL (§18). The Jasper template wires every field today; the dormant ones render blank until their respective backend ships, with no template revisits required.

Printed Reports Configuration

Lab-wide settings that apply to every printed report generated by OpenELIS. Changes take effect on the next report generation; no restart required.

Printed report paper size *
Choose the paper size used when generating PDFs for patient reports, result reports, and all other printed outputs. US Letter is the default for deployments in the United States; A4 is the default for most other countries.
Implementation note: The report generator resolves the template at runtime via configService.getValue("printedReport.defaultPaperSize", "LETTER"). Both JRXMLs live in src/main/resources/reports/; the legacy patient.jrxml stays on disk for one release.
